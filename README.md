# LSTM 趋势预测服务

基于 LSTM 深度学习模型的加密货币趋势预测服务。

## 功能

- 趋势预测：看涨 / 中性 / 看跌
- 置信度分析
- 实时预测

## 快速开始

### 1. 安装依赖

```bash
cd python-ml
pip install -r requirements.txt
```

### 2. 启动服务

```bash
python app/main.py
# 或
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

### 3. 访问 API

- API 文档: http://localhost:8000/docs
- 健康检查: http://localhost:8000/health

## API 接口

### 训练模型

```bash
POST /train
{
  "symbol": "BTCUSDT",
  "use_sample_data": true,
  "epochs": 50
}
```

### 预测趋势

```bash
POST /predict
{
  "symbol": "BTCUSDT",
  "use_sample_data": true
}
```

### 获取模型状态

```bash
GET /features?symbol=BTCUSDT     # 当前特征权重
GET /health                      # 健康检查
GET /self-learn?symbol=BTCUSDT&interval=1h   # 手动触发一轮自我学习巡检
```

### 两条独立通路：模型用收盘价，仓位层用实时价

这是本项目最重要的一条架构约束，**不要合并它们**：

```
通路 A（模型）  klines = fetch(..., drop_unclosed=True)   ← 只用已收盘 K 线
                prediction = model(klines)                  ← 一个字段都不改

通路 B（仓位）  live.price                                  ← 实时价标量
                position_manager.step(live.price, effective_signal)
```

**为什么不能把"正在走的那根"拼进模型输入**（实测，`experiments/partial_bar_probe.py`）：

| 半根走到 | 中位振幅 `high_low_ratio` | 相对同一批小时的完整 bar |
|---|---|---|
| 完整 60 分钟 | 0.00366 | 100% |
| 45 分钟 | 0.00358 | 97.8% |
| 30 分钟 | 0.00247 | **67.5%** |
| 15 分钟 | 0.00193 | **52.7%** |

半根 K 线的振幅被**系统性压缩**（模型训练里每根都是完整的 60 分钟），这是有方向的偏差
——会让模型系统性低估波动，而不是随机噪声；`high_low_ratio` 恰好在极端行情 OOD 排序里列第三。
实测**方向被改变的比例 13.3%**（83 样本，95% 区间 [7.6%, 22.2%]），含完整反向；根因是模型
概率极平（约 35/31/34，仅略高于均匀分布 33.3），argmax 本就由噪声主导。

**为什么仓位层必须用实时价**：它要算的是未实现盈亏和止损，输入是一维的**价格**，
没有训练分布问题。反过来，`current_price` 是**最后一根已收盘 K 线的收盘价**，
实测滞后 0~59 分钟（1h 周期）——拿它做实时判断，在瀑布行情里会被误导。这也是
`current_price_basis` 字段存在的原因。

取不到实时价时 `live.price` 为 `null` 且 `live.error` 非空；**不要**把 `null` 当 0 用
（`services.live_price.position_guard()` 就是给这个用的）。用 `LIVE_PRICE_ENABLED=false`
可以关掉这次额外的 HTTP 往返。

### 信号状态机（`position_state`）

模型每根 K 线独立决策 → 方向翻转频繁 → 换手极高。`services/signal_state_machine.py`
把"每根重新决策"改成"进入状态后维持，直到被确认打破"：

```
BULLISH ──分数衰减──> WEAK_BULLISH ──空头确认──> BEARISH
   │                       │                     │
   └──跌破失效线───────────┴─────────────────────┘
                      ↓
                   NEUTRAL
```

三层确认：**迟滞双阈值**（进入需越过 `*_enter`、退出回到 `*_exit`，中间保持）+
**连续确认**（`confirm_bars` 根，过滤单根假信号）+ **价格失效线**
（进入时记录 `signal_price`，跌破 `signal_price*(1-stop_pct)` 则失效并**锁住**，
等新信号才解除）。可选叠加 `highest - N*ATR` 移动失效线与 HH/HL→LH/LL 结构确认。

⚠️ **阈值必须按模型自身分数分布标定**。模型 `directional_score` 实测只在
**47.54~51.88**（p10 48.88 / p50 49.84 / p90 50.86）之间，因为概率极平
（线上 看跌35.4/中性31.19/看涨33.41）。所以：设计上"P(up) ≥ 60%"永远到不了；
写死 70/30（旧 `trend_manager` 默认）方向输出恒为 0；写死 55/45 实测 240 根零切换。
实际使用模型目录 `*_train_meta.json` 里训练期标定的 `calibrated_thresholds`。

**OOS 实测（fit 窗口之后，每币种 2453 根，5bp/边）**：

| 币种 | argmax 净 / 毛 | 状态机 净 / 毛 | 净差 | 切换次数 |
|---|---|---|---|---|
| BTCUSDT | −17.59% / −4.01% | **+17.37%** / +21.01% | +34.96% | 152 → 36 |
| ETHUSDT | −29.79% / −20.79% | **+9.90%** / +10.46% | +39.69% | 120 → 9 |
| SOLUSDT | −48.89% / −44.27% | −15.56% / −14.49% | +33.34% | 86 → 23 |
| 等权组合 | −32.09% | **+3.91%** | **+36.00%** | 119 → 23 |

**3/3 币种一致改善，且毛收益同时改善**（不只是省手续费）。复现：
`experiments/state_machine_validate.py`（走生产代码路径）。

⚠️ 边界：该验证用的是**单一固定模型**（fit 到 2026-06-11）在之后 2453 根上的表现，
样本偏短；`stop_pct`/`confirm_bars` 是在重叠样本上选的，存在参数选择偏差。
`SIGNAL_STATE_MACHINE_APPLY` 因此默认 `False` —— 只给建议，不覆盖 `effective_signal`。

### 字段语义（务必按这里理解）

| 字段 | 含义 |
|---|---|
| `prediction.prediction.confidence` | **最终所报方向对应的概率**（0-100）。不是 softmax 最大值 —— 最大值可能落在"中性"类上，那样报出来的数字与方向无关。 |
| `max_probability` / `max_probability_class` | softmax 最大值及其类别（"模型最倾向哪一类"），独立于所报方向，便于排查。 |
| `directional_score` | **多空分离度**（50 = 模型完全无方向）。由 `50 + 50*(p_bull - p_bear)` 合成，再叠加价格动量与 S 曲线放大得到用于判定的分数。 |
| `required_score` | 给出方向所需越过的分数（默认看涨 70 / 看跌 30）。**报"中性"时看这两个字段就知道差多远**。⚠️ `TREND_MANAGER_ENABLED=False`（**默认**）时状态机不参与决策，它与 `trend_score`、`entry_price` 一律为 `null`，且 `decision_source` 为 `model_argmax`。上面的示例就是默认配置下的真实输出。 |
| `probabilities` | 三类概率，**数值**（0-100，和为 100）；展示用字符串见 `probabilities_pct`。 |
| `model_bias` | 趋势状态机判定的模型当前倾向（看涨/看跌/中性）。 |
| `effective_signal` | **下游应当采用的权威方向**（`source` 标明来自 `model` 还是 `signal_reversal`）。 |
| `signal_reversal.applied` | 反转建议是否真的覆盖了模型输出（默认配置为 `false`，只给建议）。 |
| `signal_reversal.message` | 人类可读结论，标明判定用的是哪两根 K 线：`基准 X → 上根收盘 Y`，有实时价时再附 `（实时 Z）`。按价格量级自适应小数位（BTC 两位带千分位、DOGE 六位）。**`Y` 不是现价**，是上一根已收盘 K 线的收盘价。 |
| `current_price_basis` | 恒为 `"last_closed_bar_close"`：声明 `current_price` 是**最后一根已收盘 K 线**的收盘价，不是实时价。 |
| `prediction_horizon_bars` / `_minutes` | **本次预测的视界**：方向只针对未来这么多时间。生产为 `1` 根（1h → 60 分钟）。⚠️ **`prediction.trend` 不是多日趋势判断**，这一点必须在接口层明说 —— 否则"BTC 两小时涨 3.6% 而模型报看跌"会被读成自相矛盾。 |
| `live.price` | **实时价**（正在走那根的最新成交价）。仅供仓位/风控层使用，`live.for_model` 恒为 `false`。取不到时为 `null`。 |
| `position_state` | 信号状态机的当前状态：`state`（BULLISH/WEAK_BULLISH/NEUTRAL/WEAK_BEARISH/BEARISH）、`position`（建议仓位）、`signal_price`、`invalidation_price`、`bars_in_state`、`structure`、`latched`、`reason`。**`applied=false`（默认）时仅给建议**，`effective_signal` 仍来自模型。状态只在新的已收盘 K 线出现时变化，同小时内结果被缓存。 |
| `live.forming_bar` | 正在走的那根的进度：`elapsed_minutes`/`progress`/`complete` 以及 OHLCV 快照。**不要拼进模型输入**（原因见上文实测）。 |

`signal_reversal.message` 的五种取值（阈值默认 0.10%，回溯默认 1 根，基准恒为**本次预测所用 K 线的上一根**，不是预测记录里的历史价）：

| 情形 | 文案 |
|---|---|
| \|价差\| ≤ 阈值 | `… 未超过阈值 0.10%，维持模型方向（基准 X → 上根收盘 Y）` |
| 模型看涨且价涨 / 看跌且价跌 | `… 与模型方向（看涨/看跌）一致，无需反转（基准 X → 上根收盘 Y）` |
| 模型**中性**且 \|价差\| > 阈值 | `… 已超过阈值 0.10%，但模型方向为中性，无方向可反转（基准 X → 上根收盘 Y）` |
| 方向矛盾 + `SIGNAL_REVERSAL_APPLY=false` | `… 与模型方向（…）矛盾，建议反转为…（当前配置为仅建议，不覆盖模型输出；基准 X → 上根收盘 Y）` |
| 方向矛盾 + `SIGNAL_REVERSAL_APPLY=true` | `… 与模型方向（…）矛盾，已反转为…` |

拿到实时价时，末尾会再附一个 `（实时 Z）`，`Z` 来自 `live.price`。**`Y` 是上一根已收盘
K 线的收盘价，不是现价**（滞后 0~59 分钟）—— 早期文案把它写成"现价"，与同一份响应里的
`live.price` 自相矛盾（线上实测：文案"现价 84,653.71" vs `live.price` 84,583.43），现已改为"上根收盘"。
实时价**只影响文案**，不参与判定；判定只用已收盘 K 线。

中性那一栏单独列出：中性没有方向可言，早期实现统一说"与模型方向一致"，在价格明显波动时读起来自相矛盾。

## 预测目标可学性（实验结论）

用 `experiments/probe_targets.py` 做了目标探针：同一套特征管线、同一套样本外方法，
把预测目标换成不同候选，看能否显著超过**最强常量基线**（多数类）。
数据：BTCUSDT 1h 共 12000 根（2025-05 ~ 2026-09），训练段 70% / 留出段 3600 根（约 5 个月）。

| 目标 | 全部样本 | 非重叠子样本* | 结论 |
|---|---|---|---|
| `dir_h1_3c` H=1 三分类（生产目标） | 39.79% vs 33.95% (+5.83pp, p<0.001) | H=1 无重叠问题 | ✔ 有微弱但显著优势（3 个种子 40.06%±0.37pp），4/4 分块均占优 |
| `dir_h1` H=1 二分类 | 51.17% vs 50.10% (+1.07pp, p=0.151) | — | ✘ |
| `dir_h4` / `dir_h12` / `dir_h24` | 见 `data/probe_results.json` | 非重叠后 ≈ 基线或更低 | ✘ **拉长视界无帮助** |
| `vol_regime` H=12 波动率状态 | 54.65% vs 52.51% (p=0.005) | 54.85% vs 51.84% (+3.01pp, **p=0.163**) | ✘ 重叠修正后不显著 |
| `breakout` H=12 突破 | 58.75% vs 51.62% (p<0.001) | 62.54% vs 50.17% (+12.37pp, p<0.001) | ✔ 但见下方"机械产物" |
| 打乱标签对照 | 33.79% vs 33.95% | — | ✓ 管线无泄漏 |

\* 多根视界的标签在相邻样本间**重叠**，名义样本数被高估，二项检验会过度显著
（breakout 的 p 从 0.000 变成 0.054、edge 从 +13.2pp 缩到 +10.6pp）。
只有"每 H 根取一个"的非重叠子样本才配得上显著性检验。

### 三个必须知道的结论

1. **`breakout` 的"可预测"是标签定义的机械产物，不是交易优势。**
   按"价格在近 12 根区间中的位置"分桶，突破发生率是 22.1% / 43.2% / 75.7%（下/中/上三分之一）
   —— 标签几乎等价于"价格是否贴近近期高点"。而且模型复杂度越高越差：

   | 模型 | 非重叠样本准确率 |
   |---|---|
   | 单特征（区间位置） | **75.25%** |
   | 逻辑回归（17 维最后一根） | 71.24% |
   | LSTM（17 维 × 60 步，即生产架构） | 62.54% |

   **一个单特征胜过全套深度管线 12.7pp。** 要做这类目标必须先控制区间位置这个混淆项。

2. **生产状态机在吃掉模型本就不大的优势。** 用同一批留出概率喂三态状态机：

   | 阈值 | 方向输出占比 | 全部预测准确率 | 方向信号精度 vs 基础发生率 |
   |---|---|---|---|
   | 70/30（生产默认） | 0.0% | 32.23%（**低于基线 33.95%**） | — |
   | 55/45 | 1.4% | 32.20% | 23.1% vs 34.0% |
   | 52/48 | 19.0% | 33.48% | 34.5% vs 34.0% |
   | 51/49 | 32.0% | 34.76% | 35.7% vs 34.0% |
   | （原始 argmax，无状态机） | 100% | **37.70 ~ 40.32%** | — |

   没有任何一种阈值配置能超过"直接用模型 argmax"。当前 70/30 是沿用旧评分尺度定的，
   与现在 `directional_score` 的实际分布（43.6 ~ 58.0）完全不匹配，所以永远不发声。

3. **数据量是当前最大的瓶颈。** 同一架构：训练 3200 行时对基线 +0.75pp（p=0.34，无优势）；
   训练 8400 行时 +5.83pp（p<0.001，3 种子稳定）。**先把训练数据从 4000 根提到 12000+ 根**，
   比调网络结构更有效。

### 下一步建议（按证据强度排序）

1. **扩数据**：生产模型用 12000+ 根训练（已验证能带来 +5pp 级别优势）。
2. **重估状态机**：按模型实际 `directional_score` 分布标定阈值，或先不用状态机（原始 argmax 更好）。
3. **放弃**"更长视界的方向预测"与"波动率状态"这两个方向（无显著优势）；
   但"多币种"不该放弃 —— 见上节修正后的结论。
4. 若要做 `breakout` 类目标，先剥离区间位置的影响，否则只是在重新发现标签定义。

实验可复现：`experiments/probe_targets.py --cache data/probe_btc_12k.json --bars 12000 --fit-ratio 0.7 --shuffle-control`

### 滚动前向验证与模型复杂度（实验结论）

`experiments/walk_forward.py`：expanding-window 滚动前向验证，每折**只用在它之前的数据**
重新训练（特征权重、标准化统计量、模型全部重拟合），共 4 折 × 3000 根 = **11996 个样本外预测点**
（约 16 个月），对比基线 = 每折的多数类。

| fold | 训练行 | 测试行 | 基线 | LSTM(17×60) | 逻辑回归(17×1) | 逻辑回归(top5) | 梯度提升树 |
|---|---|---|---|---|---|---|---|
| 0 | 14000 | 2999 | 35.1% | 40.0% | 36.8% | 35.7% | 36.7% |
| 1 | 17000 | 2999 | 35.6% | 42.7% | 41.6% | 39.0% | 39.1% |
| 2 | 20000 | 2999 | 37.5% | 41.5% | 41.2% | 40.2% | 38.4% |
| 3 | 23000 | 2999 | 34.4% | 42.2% | 41.8% | 41.8% | 37.7% |
| **合并** | | **11996** | **35.64%** | **41.63% (+5.99pp, p=4e-42, 4/4 折占优)** | 40.38% (+4.74pp) | 39.18% (+3.54pp) | 38.01% (+2.38pp) |

结论：

1. **优势不是单段行情的运气**：4 折全部超过各自基线（+4.9 / +7.1 / +4.0 / +7.8pp），
   合并 +5.99pp、p≈4e-42。单窗口那次 +8.19pp 偏乐观，**稳健口径是 +6pp 左右**。
2. **深度模型只是略胜**：一个**只看窗口最后一根特征**的逻辑回归就拿到 +4.74pp，
   相当于 LSTM 优势的约 79%；60 步时序建模额外带来约 +1.25pp。
   top-5 特征子集丢约 1.2pp；梯度提升树在 3 分类上反而最差（+2.38pp，疑似过拟合）。
   → 若运维成本敏感，用逻辑回归即可；要最好效果则保留 LSTM。
3. **各折选出的 top-5 特征高度稳定**：`high_low_ratio`、`ichimoku_kijun_sen`、`price_change_pct`、
   `close_open_ratio`、`ichimoku_tenkan_sen` —— 都是简单的价格几何量，
   与现有加权分析器偏好的 `ma_ratio_5_20` / `adx` / `stoch_d` / `macd_histogram` 并不一致，
   值得重新审视特征加权环节。

### 特征加权：一个被 scaler 抵消的无效环节（实验结论）

早期实现把指标权重乘在逐列标准化**之前**（`(x-μ)/σ * w`），而下游紧接着是 `StandardScaler`
—— 后者逐列减均值、除标准差，会把任何非零的按列常数乘子**精确抵消**。
实测：把权重从"近似均匀"换成"极端不均匀"，模型输入的最大差异只有 **3e-15**（浮点噪声）。
也就是说那一版加权对模型**完全没有影响**，是纯无效复杂度；接口里返回的 `feature_weights`
也因此不具备"驱动模型"的含义。

现在的处理：

1. **输入路径**统一为 `build_input_matrix`：逐列标准化 → scaler →（可选）加权。
   旧模型仍按历史管线处理（`input_pipeline="weighted"`），新训练标为 `"normalized"` ——
   两者数学等价，但**必须知道 scaler 是在哪种矩阵上拟合的**，否则输入会被整体放大
   约 `1/w ≈ 17` 倍（这是本次改动中最危险的一步，已用测试钉住）。
2. **真正生效的加权**（`FEATURE_WEIGHTING="mutual_info"`）放在标准化**之后**，
   权重来自训练段互信息，随模型持久化。
3. `/features` 现在明确标注 `feature_importance_role="diagnostic_only"`，
   并在启用时返回 `mutual_information` / `applied_feature_weights`。

**但实测下来 MI 加权并不划算**（多币种各 2 折、每折 2000 根样本外）：

| 币种 | 不加权 | MI 加权 | 基线 |
|---|---|---|---|
| BTCUSDT | **+5.70pp** | +4.95pp | 35.34% |
| ETHUSDT | +0.83pp | −0.58pp | 37.44% |
| SOLUSDT | −1.48pp | −2.55pp | 39.67% |

三个币种上 MI 加权都比不加**更差**，因此默认保持 `FEATURE_WEIGHTING="none"`。
机制已实现并保留开关，但这个负面结论是实测出来的，不是猜的。

### 多币种：能提取信息，但强弱分明（实验结论，含一次结论修正）

`experiments/multisymbol_folds.py`：**完全相同的配方**（1h、12000 根训练、同一套 17 维特征、
同一套标签与切分）在三个币种上各做 2 折滚动前向验证，每币种 3998 个样本外预测点。

**务必用平衡准确率看，不要只看"总准确率 vs 多数类基线"。** 后者会系统性冤枉高波动币种：
±0.1% 的固定标签阈值与波动率相互作用 —— 波动越高，"中性"占比越小、多数类基线越高
（BTC 中性 33%、基线 33.7%；SOL 中性 22%、基线 39.8%）。一个把预测铺在三类上的模型，
在这种不均衡标签下天然打不过"恒定猜多数类"。

| 币种 | 1h 波动 | 类分布(跌/平/涨) | 总准确率 / 多数类基线 | **平衡准确率 / 随机** | 各折占优 |
|---|---|---|---|---|---|
| BTCUSDT | 0.44% | 33/33/34 | 41.05% / 35.34% (+5.70pp) | **40.95% / +7.61pp** | 2/2 |
| ETHUSDT | 0.67% | 36/27/37 | 38.27% / 37.44% (+0.83pp) | **37.72% / +4.39pp** | 2/2 |
| SOLUSDT | 0.73% | 38/22/40 | 38.19% / 39.67% (−1.48pp) | 33.21% / −0.12pp | 0/2 |

逐类精度提升（生产模型，各币种 2399 个样本外点，对比该类基础发生率）：

| 币种 | 看跌 | **中性** | 看涨 |
|---|---|---|---|
| BTCUSDT | +4.6pp | **+12.2pp** | +0.5pp |
| ETHUSDT | +2.8pp | **+8.2pp** | +5.1pp |
| SOLUSDT | +1.9pp | **+6.7pp** | +0.0pp |
| BNBUSDT | +2.9pp | **+6.4pp** | +2.6pp |

结论（修正后的版本）：

1. **这套方法不是"BTC 专用"**。四个币种的平衡准确率**都高于随机**（BTC +7.6pp、ETH +4.4pp、
   BNB/ SOL 的逐类提升也都在），"中性"类的精度提升在四个币种上都是 +6.4~+12.2pp。
2. **强弱分明**：BTC 最强，ETH 次之，BNB 中等，**SOL 是唯一没有净优势的**（平衡准确率
   33.21% ≈ 随机，0/2 折占优）。
3. **共性的强项与弱项很一致**：所有币种都是"识别中性/低波动 K 线"最强（+6~12pp），
   而"方向判断"最弱且不稳定（看涨提升 0 ~ +5.1pp）。
4. **统计功效的教训**：n≈4000 只能分辨 ≥2pp 的差异；要测出 +1pp 需要约 14k 样本。
   因此"ETH 无优势"这种说法超出了数据支持范围 —— ETH 的 +0.83pp 只能说明
   "未测出 ≥2pp 的差异"，不能说"没有优势"。
5. **真正按 BTC 标定的是标签阈值**（固定 ±0.1%），不是模型或特征。要让任务在各币种间可比，
   阈值应随波动率自适应（如 ±k·σ，σ 取过去 60 根收益标准差）；这需要**重新训练**
   （标签变了），是下一步该做的实验。

### 标签定义 A/B/C 对比：任务可比了，但优势没有变大（实验结论）

固定阈值 ±0.1% 把"波动"当成绝对量：同一个 0.1% 对 BTC 可能是真实波动，对 SOL 可能只是噪声
—— 于是同一个阈值在不同币种上定义了**难度不同的任务**。按可插拔标签设计做了三组对照
（`services/labeling.py` + `experiments/label_experiments.py`，**生产默认仍是 A，未被替换**）：

- **A** `fixed`：固定 ±0.1%（生产口径，对照基准）
- **B** `volatility`：`threshold = k·σ`（σ = 过去 60 根收益标准差），k ∈ {0.5, 0.8, 1.0}；
  另实现了相对 ATR 版本
- **C** `quantile`：用**过去 500 根**收益的滚动分位数当阈值（因果实现）

**① 标签侧结论（确定性，与模型无关）——你的判断成立：**

| 标签模式 | BTCUSDT | ETHUSDT | SOLUSDT | 跨币种是否一致 |
|---|---|---|---|---|
| A 固定 ±0.1% | 34/31/34%，基线 35% | 36/26/37%，基线 37% | 39/22/40%，基线 40% | ✘ 差异大 |
| B k=0.5 | 25/50/25%，基线 50% | 23/53/24%，基线 53% | 25/49/26%，基线 49% | ✔ 基本一致 |
| B k=1.0 | 12/77/11%，基线 77% | 10/79/11%，基线 79% | 12/75/12%，基线 75% | ✔ 基本一致 |
| C 历史分位 | 27/47/27% | 27/47/26% | 27/45/28% | ✔ 基本一致 |

A 下"中性"占比 31%→26%→22%、多数类基线 35%→37%→40%，三个币种的**任务难度明显不同**；
B/C 之后三个币种的类别分布几乎重合 —— 这正是"跨币种公平比较"想要的。
（C 的中性占比 47% 而非 33%，因为加密数据存在波动率聚集，滚动分位带偏宽；不是三类各 1/3。）

**② 模型侧结论（补种子后可以判定了）：标签归一化确实抹平了"币种难度差"，代价是 BTC 的优势缩水。**

单次运行不足以比较标签模式 —— 同一配置换随机种子重训，平衡准确率 σ≈1.9pp、极差可达 3.8pp，
比待比较的差异还大。补到**每单元格 3 个种子**后（27 次训练，`experiments/label_experiments.py --seeds 3`）：

| 币种 | A 固定 ±0.1% | B σ归一化 k=0.8 | C 历史分位 |
|---|---|---|---|
| BTCUSDT | **37.57% ±0.76**（+4.24pp） | 34.96% ±1.26（+1.63pp） | 35.00% ±0.98（+1.67pp） |
| ETHUSDT | 36.07% ±0.99（+2.74pp） | 35.71% ±0.91（+2.38pp） | 35.71% ±0.23（+2.37pp） |
| SOLUSDT | 33.37% ±0.35（+0.03pp） | 33.59% ±0.08（+0.26pp） | **34.63% ±0.67**（+1.30pp） |
| **币种间极差** | **4.20pp** | 2.12pp | 1.08pp |
| **BTC−SOL 差距** | **+4.21pp（5.0σ，显著）** | +1.37pp（1.1σ，不显著） | +0.38pp（0.3σ，不显著） |

（±为种子间标准误；括号内为相对随机 33.33% 的优势）

1. **A 的"币种难度差"是真实的、且被标签归一化消除了**：A 下 BTC 比 SOL 高 4.21pp
   （37.57±0.76 vs 33.37±0.35，5.0σ）；换成 B 后降到 1.37pp（1.1σ）、C 后降到 0.38pp（0.3σ），
   **在统计上都与 0 无法区分**。所以"BTC 专用"这个印象，主要来自固定阈值与各币种波动率的交互。
2. **代价是 BTC 的优势缩水**：A → C 在 BTC 上是 **−2.57pp**（需要约 2.3 个种子/侧即可分辨，
   3 个种子已够）。ETH 基本不变（−0.37pp，要 38 个种子才分辨得出 → 实质无差异），
   SOL 反而 **+1.26pp**（+0.03pp → +1.30pp）。
3. **公允标签下的真实水平**：B/C 下三个币种的平衡准确率都在 **+1.3 ~ +2.4pp** 区间 —— 
   小而一致，不再有 BTC 一枝独秀。**A 报出的 +4.2pp（BTC）里有约 2.6pp 是标签假象。**
4. **A 那 +4.2pp 的来源也能看清了**：A 下 BTC 的"中性类精度提升"是 **+17.74pp**，
   换成 C（阈值按波动归一）后掉到 **+3.45pp**。也就是说 A 下很大一块"优势"其实是
   "识别低波动区间"这个更容易的成分 —— 它被固定阈值直接编码进了标签，
   而波动归一化把它拿掉了。SOL 更极端：A 下该指标是 **−3.14pp（反号）**，C 下是 **+6.14pp**。

**③ 仍然站得住的结论：**

1. 没有任何一种标签定义让模型出现"强优势"：30 个单元格全部落在 +6pp 以内，
   多数在 +0~+3pp。**换标签不会凭空造出预测力。**
2. 旧指标（总准确率 vs 多数类基线）在 B 下彻底失效：B 的标签有 50~79% 是"中性"，
   模型不追多数类，于是准确率显示 −13 ~ −54pp（看着像灾难），而平衡准确率只有 ≈随机。
   这类比较**必须**用平衡准确率或逐类精度，否则结论完全被类别分布主导。
3. 逐类精度（生产模型、2399 个样本外点）显示：真正的稳定优势在"中性/低波动"识别
   （BTC +12.2pp、ETH +8.2pp、SOL +6.7pp、BNB +6.4pp），而方向类很弱（看涨 +0.0~+5.1pp）。
   这也解释了为什么把阈值改成波动率归一化后优势会缩水 —— 它正是把"这根是不是低波动"
   这个最容易的成分从标签里拿掉了。

### 盈亏评估：毛收益是真的，手续费把它吃光了（实验结论）

分类指标已经探到底（公允标签下平衡准确率优势只有 +1~2.4pp），所以把信号接到最简仓位规则上
直接看钱：`experiments/pnl_backtest.py`。规则**不含任何调参**：

    看涨 → +1 单位；看跌 → -1 单位；中性 → 空仓
    每根 K 线收盘按信号调仓，持有到下一根收盘
    换手成本 = |仓位变化| × 手续费

严格样本外：expanding-window 滚动前向，每折只用该折之前的数据重训，拼接各折权益曲线；
3 币种 × 4 折 × 3000 根 = 每币种 **11992 根 1h（1.37 年）** 样本外。

| 币种 | 毛收益(0bp) | 净@5bp | 净@10bp | Sharpe@5bp | 最大回撤 | 换手次数 | 胜率 | 置换检验 p |
|---|---|---|---|---|---|---|---|---|
| BTCUSDT | **+138.28%** | **−20.30%** | −73.37% | −0.24 | 38.0% | 2190 | 50.9% | 0.015 |
| ETHUSDT | +41.35% | **−27.02%** | −62.34% | −0.09 | 71.0% | 1321 | 50.8% | 0.270 |
| SOLUSDT | +30.43% | **−12.54%** | −41.38% | +0.20 | 55.0% | 799 | 49.4% | 0.270 |
| 等权组合 | — | **−7.94%**（年化 −5.86%） | — | −0.01 | 34.5% | — | — | **0.033** |

同一区间的基准：BTC 买入持有 −16.23% / 恒定做空 −5.30%；ETH 买入持有 **+44.61%**（策略因 39% 时间做空而大幅跑输）；
SOL 买入持有 −23.51% / 恒定做空 −31.43%（策略 −12.54% 是三者里最好的，但仍为负）。

**核心结论：每单位换手的毛收益 < 每单位换手的成本。**

| 币种 | 每单位换手毛收益 | 每次换手成本@5bp | 盈亏平衡手续费 |
|---|---|---|---|
| BTCUSDT | 6.31bp | 5.0bp | **3.96bp** |
| ETHUSDT | 3.13bp | 5.0bp | **2.62bp** |
| SOLUSDT | 3.81bp | 5.0bp | **3.32bp** |

即：策略只在**手续费低于约 2.6~4.0bp/边**时才不亏；而现实费率是 5bp（合约 taker）到 10bp（现货）。
换手 799~2190 次意味着平均每 5~15 根 K 线就换一次仓，费用按 `(1−f)^换手` 复利吞噬本金 ——
BTC 在 5bp 下的费用因子是 `0.9995^2190 ≈ 0.334`，把 +138% 的毛收益压成 −20%。

**置换检验给出的是另一个维度的信息**：把仓位序列做循环移位（保持仓位分布与换手结构、
只破坏与收益的时间对齐）后，零分布的收益是 −66%/−38%/−32%（BTC/ETH/SOL），
组合 p=0.033、BTC 单币 p=0.015。**说明信号的"时间对齐"确实携带信息** ——
它不是靠长期偏多/偏空碰上行情的结构偏差；**问题在于单次交易的信息量小于单次交易的成本。**

因此下一步的方向不是换模型，而是**降换手**：滞后/最短持有期（注意：之前因为"伤准确率"被我
关闭的 `TREND_MANAGER_ENABLED` 状态机，正是为抑制抖动设计的，应当在 P&L 口径下重新评估）、
只在高确信度时交易、或拉长视界让每笔的边际收益大于手续费。

### 极端行情下的行为，以及"仓位能不能被避免"（实验结论）

一组针对"已持有多仓时遇到暴跌"的实测。全部复用 `data/pnl_backtest.json` 的 OOS 逐 bar 产物，
或走生产同一条代码路径，**没有重新训练**。

| 脚本 | 回答的问题 | 关键结论 |
|---|---|---|
| `experiments/shock_response.py` | 冲击 K 线上模型的事前方向准不准 | 合并三币种：极端 1% 桶事前命中 **45.7%** vs 基线 50.9%（z=−1.91）；\|涨跌\|≥2% 桶 **45.8%**（z=−2.38）。**冲击时"给方向"的比例 93.6% 反而高于平时 85.7%** —— 模型在极端行情下不收手，更爱表态 |
| `experiments/shock_ood.py` | 冲击把模型输入推到训练分布之外多远 | 极端 1% K 线 **100%** 至少一个特征 >3σ（平时 4.2%），**42.5%** >5σ；平均 3.23 个特征越界（平时 0.07）。最远的是 `price_change_pct`/`close_open_ratio`/`high_low_ratio` |
| `experiments/shock_replay.py` | 真实暴跌逐时点回放 `/predict` 会返回什么 | 2026-09-04 BTC −2.18% 那根：**盘中 59 分钟完全看不见**；收盘后模型 **仍然看涨且置信度从 38.54 升到 44.93**（暴跌把中性概率从 23.2 砍到 11.8）；反转建议只活 1 根 K 线 |
| `experiments/partial_bar_probe.py` | 把未收盘那根加回模型会怎样 | 半根振幅被系统性压缩（30 分钟只有完整 bar 的 67.5%），方向被改变 **13.3%**（[7.6%, 22.2%]） |
| `experiments/position_recovery.py` | 信号转中性 / 冲击后空仓能否救回仓位 | 548 个 \|冲击\|≥2% 事件里 **281 个（51%）冲击后反弹**；叠加"空仓一根"规则后等权组合 **−19.96% → −33.97%**，即**更差** |
| `experiments/stop_loss_probe.py` | 盘中止损会不会被假触发打脸 | 触发中 **87–91% 是假触发**（盘中插到止损位、当根收盘又涨回），只有 6–13% 是真该止损 |
| `experiments/vol_target.py` | 事前缩仓有没有用 | **唯一有效**：目标波动 0.4%/根时，冲击事件锁死损失 −139% → **−94%（−32.6%）**，冲击前平均仓位降到 55%；全周期最大回撤 **−54.66% → −43.98%**，而净收益几乎不变（−19.96% → −20.09%） |

**结论：能"避免"的只有信号层面的东西；仓位层面只能"缩小"和"权衡"。** 止损与收盘后改信号
都晚一根（冲击那根已经吃满），唯一不依赖预测、也不被假触发惩罚的是**事前波动率缩仓**。
详见 `README` 的两条通路一节与 `services/live_price.py`。

## 口径与风险（重要）

- **方向由模型 argmax 决定，状态机默认关闭**（`config.TREND_MANAGER_ENABLED = False`）。
  实测（同一模型、同一批概率、留出段 3600 根）：
  原始 argmax **37.70% ~ 40.32%**，而状态机各种阈值配置只有 **32.20% ~ 34.76%**
  —— 没有任何一种能超过 argmax，且 70/30 下方向输出恒为 0（分数实际只在 43.6~58.0）。
  需要方向平滑时再打开；打开后使用训练期按模型自身分数分布标定的阈值
  （`*_train_meta.json` 的 `calibrated_thresholds`），而不是写死的 70/30。
- **当前模型的样本外表现**（BTCUSDT 1h，12000 根训练，留出段 2026-06-12 ~ 2026-09-19
  共 2369 个预测点，走生产 `predict` 路径）：

  | 指标 | 数值 |
  |---|---|
  | 总体准确率 | **41.87%** |
  | 多数类基线（常量） | 33.68% |
  | 优势 | **+8.19pp**（单窗口；滚动前向验证的稳健估计是 **+5.99pp**，见下） |
  | 信号构成 | 看跌 1469 / 中性 694 / 看涨 206 |
  | 分类精度 | 看跌 37.64% · 中性 51.59% · 看涨 39.32%（三类基础发生率均约 33.3%） |

  即：**优势是真实的，但主要体现在识别"中性/低波动"这类 K 线（51.6% 精度），方向性呼唤
  只有 37~39% 精度**（基础发生率 33.3%）。这不是能直接下单的信号强度。
- **数据量是当前最大的杠杆**：同一架构、同一目标，训练 3200 行时对基线 **+0.75pp**
  （p=0.34，无优势），训练 8400 行时 **+5.83pp**（p<0.001，3 种子稳定）。
  因此生产模型已从 4000 根扩到 12000 根（val_acc 0.3750 → **0.4067**）。
- **历史记录**：修复前（4000 根模型 + 状态机 70/30）在同一类样本外区间上只有 25.20%
  准确率、且 4337 条预测**全部为"中性"**（= 常量基线，不含方向信息）。
  更早的版本曾报出 38.6%，那是"不对称阈值（`>=70` 看涨 / `<50` 看跌）+ 两态状态机"的产物
  （71% 的预测是看跌），并非模型的方向判断力。**信号请勿直接当作交易依据。**
- **训练目标 = 推理目标 = 评价目标**：标签定义为「窗口最后一根 → 下一根」，
  训练（`prepare_data`）、线上记录（`PredictionTracker`）、回测与评估
  （`services/backtest_utils.next_bar_label`）四处同一口径。此前训练标签用"行 i → 行 i+1"
  跳过了紧邻窗口的那一根（还会让最后一条训练样本的标签越界到验证段）；
  `evaluate_model.py` 也曾整体错后一根；回测早期版本更是拿"距上次信号变化以来的累计涨跌"
  判对错（实测 329 条预测只有 1 个锚点价）。这些都已修正并有单测钉住。
- **评估必须看样本外**：模型目录下的 `*_train_meta.json` 记录的是**真正参与拟合的窗口**
  （`train_*`，另有 `data_*` 表示输入数据范围）。`evaluate_model.py` 与两个回测脚本启动时
  自动比对并**重叠即中止**（退出码 2），除非显式加 `--allow-in-sample`。
  早期版本把输入范围当成训练窗口，会把真实留出段误判为 in-sample。
- **训练/推理口径一致**：特征顺序与标准化统计量在训练时固化并随模型持久化（`*_weight_analyzer.pkl`），
  推理原样复用；预测至少需要 120 根 K 线（60 步序列 + 60 根特征预热），否则滚动指标会被填 0 污染输入。
  取数层默认**丢弃尚未收盘的当前 K 线**（`config.drop_unclosed_klines`）：训练只见过完整 K 线，
  喂半根会让输入分布与训练不一致，标签定义（"窗口最后一根已收盘 → 下一根"）也不成立。
  原始行情导出 `/klines` 可显式传 `drop_unclosed=false` 保留实时半根。
- **特征加权的角色**：接口返回的 `feature_weights` 只是**诊断信息**（见上文"被 scaler 抵消的无效环节"），
  不驱动模型；真正能生效的加权是 `FEATURE_WEIGHTING="mutual_info"`，但实测不划算，默认关闭。
  模型输入管线有两个版本（`input_pipeline`），新模型为 `normalized`，旧模型为 `weighted`，
  切换会把输入尺度放大 ~17 倍 —— 改动输入路径时必须同时处理版本。
- **阈值统一**：标签、核对、信号反转、趋势状态机的阈值都集中在 `config.py`，不要在各处另写一套。
- **自我学习**：`/self-learn` 用「预测时点 + 视界」之后的**真实 K 线**核对历史预测，回看窗口覆盖不到的旧记录
  标记 `expired` 不参与统计；已核对样本不足 10 条时不做任何判断。

## 注意事项

- 需要 Python 3.8+
- 首次使用需要训练模型（`GET /train`、`POST /train` 或 `ultimate_train.py`）
- 训练可能需要几分钟时间
- 推荐用 `scripts/setup.sh` 建 `.venv` 安装依赖后再启动

```typescript
const response = await fetch('http://localhost:8000/predict', {

  headers: { 'Content-Type': 'application/json' },

});
const result = await response.json();
```
